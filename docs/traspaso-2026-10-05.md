## 5. Lo siguiente: las pruebas de carga

**Preparado:**

- `LIMITE_GLOBAL_POR_IP` (`src/config/limiter.ts`, validada en
  `config/entorno.ts`). El límite general de la API es de 1.000 peticiones por
  IP cada 15 minutos, y las pruebas salen todas de la IP del PC de desarrollo:
  sin subirlo, todo serían 429. Se lee en cada petición. **No se puede falsear la
  IP** para esquivarlo: el montaje del servidor solo se fía del último
  `X-Forwarded-For`, que pone el nginx del sistema.

**Pasos, en orden:**

1. Esperar a que la verificación del último commit esté en verde y desplegarlo
   con el botón (lleva `LIMITE_GLOBAL_POR_IP`).
2. Que el usuario añada en el servidor, durante la prueba:
   - `LIMITE_GLOBAL_POR_IP=1000000` en `/srv/desamparados/.env` y
     `sudo docker compose -f compose.yaml -f compose.servidor.yaml up -d api`.
   - Un usuario de la puerta solo para la carga (se borra al acabar):
     `printf 'carga:%s\n' "$(openssl passwd -apr1)" | sudo tee -a /etc/nginx/pruebas.htpasswd >/dev/null`.
   - Una medida más fina mientras dure:
     `while true; do sudo /usr/local/sbin/medir-desamparados /var/log/desamparados/carga.csv; sleep 5; done`
     (Ctrl+C al terminar).
3. Las credenciales (la de la puerta y la de una cuenta del CMS para subidas y
   mesa) las pone el usuario en un fichero de su PC que Claude no lee, por
   ejemplo `%USERPROFILE%\carga.env`; el guion las toma con `--env-file`.
4. El guion de carga, en Node (no hay k6), con varias fases de 2–3 minutos y
   subiendo usuarios a la vez (10, 25, 50, 100):
   - **Lectura pública**: portada (`/`, `/api/portada`, `/api/news/latest`,
     `/api/events`, `/api/publications/latest`, `/api/salidas/proxima`),
     noticias, fotos de `/storage/public` y los `assets`.
   - **Subidas** al CMS (`POST /api/upload/public`), que hacen trabajar a
     ClamAV y a sharp (WebP de 1920 px): fotos y algún PDF grande.
   - **Mesa de procesión**: varias conexiones al canal
     `GET /api/procesion/admin/mesa/eventos` (SSE) a la vez, con lecturas.
   - Por fase: peticiones por segundo, latencias p50/p95/p99 y errores; con el
     CSV del servidor, memoria y CPU de cada contenedor.
   - **No** usar «Hazte hermano»: manda correos reales por Gmail.
5. Al acabar: quitar `LIMITE_GLOBAL_POR_IP`, volver a levantar la API, borrar
   el usuario `carga` de `pruebas.htpasswd` (`sudo sed -i '/^carga:/d' …`) y
   limpiar las subidas de prueba (`npm run limpiar:huerfanos` en
   `herramientas`).
6. **El informe** para el usuario: si el VPS-1 basta, con cuánto margen, y qué
   se ajustaría (por ejemplo, el tope de ClamAV o compilar la API para que no
   cargue `tsx`). Se puede publicar como artifact.
