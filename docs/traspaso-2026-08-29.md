## 3. Puesta en marcha en el PC nuevo

Hace falta una **MariaDB local** con la base `desamparados_db`.

```bash
git clone <repo> && cd Desamparados
git checkout cms-edicion-y-tutores

cd backend-desamparados
npm ci
npx prisma generate          # obligatorio: el cliente no está versionado
npx prisma migrate deploy
npm run seed                 # idempotente; siembra 300 hermanos de demostración
npm run dev                  # escucha en :3001

cd ../desamparados-web
npm ci
npm run dev                  # :5173, proxy /api -> :3001
```

**El `.env` del backend no está en el repositorio.** Cópialo de
`backend-desamparados/.env.example`. Sin estas seis, el backend ni arranca
—`config/db.ts` corta antes de importar la app—:

```
DATABASE_URL  DATABASE_HOST  DATABASE_USER  DATABASE_PASSWORD  DATABASE_NAME  JWT_SECRET
```

`JWT_SECRET` se genera con `npm run gen:secret`.

## 4. Qué trae el PR #5

- **Editar en pantalla propia.** Las cinco secciones tenían un formulario al pie
  del listado que servía a la vez para crear y editar. Ahora *Editar* navega a
  `/cms/<seccion>/:id/editar` con la misma guarda de rol que su listado, y el
  formulario de arriba solo crea. El marco común es
  `features/cms/PantallaEdicion.tsx`, con Guardar confirmado y aviso de cambios
  sin guardar (`useBlocker`, que exige un *data router*).
- **Ficha del hermano completa**: dieciséis campos en cuatro bloques que el
  servidor ya devolvía y el cliente ignoraba. Los datos bancarios siguen fuera.
- **Fechas de alta y baja editables**, con la regla en
  `backend/src/domain/fechas-hermano.ts`: la baja nunca antes del alta, y quitar
  la baja reactiva al hermano.
- **Solicitudes de alta en su pestaña**, con el número de pendientes en la
  etiqueta y la vista en la URL (`?vista=solicitudes`). Antes el bloque solo
  aparecía si había alguna: la función existía y era invisible.
- **El Hermano Mayor gestiona el censo entero, como secretaría.** Las diez rutas
  de `/api/hermanos/admin` van a una sola lista, `rolesGestionCenso`.
- **Emancipar desde secretaría**: `POST /api/hermanos/admin/:id/emancipar`. La
  cuenta nace con una contraseña aleatoria que nadie conoce y al hermano le
  llega un enlace para ponérsela, válido **72 horas**.
- **Borrados con diálogo propio** en vez de `window.confirm`, nombrando lo que
  se va a borrar.
- **Barra lateral fija**: en Tesorería la página mide veinte mil píxeles.
- **Cinco solicitudes en el censo de demostración**, dos con un menor a cargo.

El plan y el diseño están en `docs/superpowers/plans/2026-08-29-cms-edicion-y-tutores.md`
y `docs/superpowers/specs/2026-08-29-cms-edicion-y-tutores-design.md`.

## 5. Decisiones que conviene revisar antes de fusionar

1. **Los tests de interfaz usan `fireEvent`, no `user-event`.** El plan daba
   `@testing-library/user-event` por instalado y no lo está; el proyecto no
   añade dependencias.
2. **Noticias, publicaciones y prendas se leen del listado del CMS**, no por id:
   el servidor no publica lectura por id para esos tres, y el listado del CMS es
   la única vista que incluye los borradores. Agenda y enseres sí la tienen. Si
   el archivo crece, pedirá un endpoint propio.
3. **El Hermano Mayor quedó igualado a secretaría en la sección de Hermanos**
   (decisión de jeiko en esta sesión). Sigue sin poder tocar la administración
   del sistema.

## 6. Dos cosas que salieron probando, no leyendo

- **El aviso de «cambios sin guardar» saltaba al guardar.** La pantalla navega
  al listado en cuanto el servidor responde y en ese momento el formulario sigue
  distinto del que se cargó, así que `useBlocker` preguntaba si se perdían los
  cambios recién guardados. Arreglado mirando también `guardando`. Afectaba a
  las cinco pantallas y **ningún test lo cogía**, porque miraban el cuerpo de la
  petición, no la navegación posterior.
- **Un 404 en una ruta que sí existía.** En el 3001 seguía escuchando un backend
  arrancado horas antes con código viejo. Ante un 404 raro, mirar primero **qué
  proceso responde y desde cuándo**:

  ```powershell
  Get-NetTCPConnection -LocalPort 3001 -State Listen | ForEach-Object { Get-Process -Id $_.OwningProcess | Select-Object Id,StartTime }
  ```

  Para no matar el servidor de nadie: `PORT=3002 npx tsx src/index.ts` y el
  frontend con `VITE_DEV_BACKEND_URL=http://localhost:3002 npx vite`.

## 7. Qué queda por hacer

**Del CMS, sin plan escrito todavía:** los listados piden una sola página con
tope fijo (100 hermanos de 300, 200 recibos de 1.167) y no ofrecen pasar de
página ni avisan de que falte nada.

**Del proyecto:**

1. **Contratar alojamiento y dominio, y desplegar.** Requiere VPS con acceso de
   administrador; un compartido con cPanel no sirve. **No hay nada contratado
   todavía**: `docs/despliegue.md` es la lista de requisitos, no la descripción
   de algo que exista.
2. **ClamAV nunca se ha ejecutado contra un `clamd` real.** Es el único trozo de
   seguridad sin verificar. Ojo: `clamd` come más de 1 GB de memoria.
3. Los PDF de las publicaciones apuntan a `pendiente.pdf`, que no existe.
4. **Bloqueado por el Grupo Parroquial**: datos de la entidad (NIF, domicilio,
   teléfono, redes, plazos del RGPD) y sustituir el contenido de ejemplo, que
   está inventado y vive en el seed.

**Pendiente menor:** el CI avisa (no falla) de *fast refresh* en
`AdminLayout.tsx:13` y `routes/index.tsx:95`, por exportar constantes junto a
componentes.
